# 보들 음성 분석 (온프레미스)

동행 매니저가 녹음한 진료 음성에서 **의사 · 환자 · 매니저**를 구분하고,
매니저가 대신 물어본 질문과 의사의 답변을 짝지어 보들 Core API로 돌려주는 서비스.

초기에는 운영자가 구분 결과를 검수하고, 그 검수가 그대로 학습 데이터가 되어
모델을 개선시킨다. 자동화는 정확도가 올라간 뒤에 넓힌다.

```
매니저 앱 (녹음)
   │
   ▼
Core API ── 오디오 ──▶ CLOVA Speech (NCP 국내 리전)
   │                      │ STT + 화자분리
   │                      ▼
   │         speaker_1/2/3 + 타임스탬프 + 텍스트
   │                      │
   │                      ▼
   │              온프레미스 AI  ← 이 저장소
   │              ① 매니저 성문 매칭 → 매니저 확정
   │              ② 나머지 역할 판정 (의사/환자)
   │              ③ Q&A 페어링 + 사전질문 대조
   │                      │
   ◀────── 구조화 JSON ────┘
   ▼
Supabase PostgreSQL → 동행 리포트
```

진료 내용 분석은 온프레미스에서 끝난다. CLOVA Speech는 NCP 국내 리전이라
국외 이전에 해당하지 않는다.

## 설계 핵심

**의사를 먼저, 따로 판정한다.** 의사와 비의사를 가르는 것이 환자와 매니저를
가르는 것보다 중요하다. 두 판정을 한 번에 최적화하면 환자·매니저 쪽 점수가
흔들릴 때 의사 판정까지 같이 흔들리므로, 의사를 독립적으로 확정하고 나머지를 배정한다.

**화자 단위로 판정한다.** 발화 하나하나를 분류하면 "네", "음..." 같은 짧은 응답에서
계속 흔들린다. 화자별로 발화를 전부 모아 한 번에 역할을 배정한다.

**매니저는 성문으로 고정한다.** 매니저는 플랫폼 소속 검증 인력이므로 자격 심사 때
음성 샘플을 받아두면 이후 모든 녹음에서 확정된다. 3명 중 1명이 확정되면 나머지는
"의사 vs 환자" 2택이 되어 난이도가 절반으로 떨어진다.

**사전 질문을 등록받는다.** 동행 요청 시 환자·보호자가 물어볼 질문을 등록하면
Q&A 매칭이 추론이 아니라 대조가 되고, 매니저가 빠뜨린 질문도 잡아낼 수 있다.

## 운영자 검수 루프

초기 정확도는 낮을 수밖에 없으므로 운영자 검수를 전제로 설계한다. 검수 결과가
학습 데이터가 되고, 그 데이터가 쌓여야 자체 모델로 넘어갈 수 있다.

운영자가 전건을 볼 수는 없으니 **신뢰도가 낮은 것부터** 큐에 올린다.
각 화자 판정에 `needs_review`가 붙고, 기준은 `REVIEW_THRESHOLD`(0.6)다.
성문으로 확정된 매니저는 검수 대상이 아니고, `UNKNOWN`은 항상 검수 대상이다.

앵커 녹음에 적용하면 이렇게 갈린다.

| 화자 | 판정 | 신뢰도 | 검수 |
| --- | --- | --- | --- |
| 참석자1 | DOCTOR | 0.77 | 통과 |
| 참석자2 | PATIENT | 0.43 | 검수 |
| 참석자3 | UNKNOWN | 0.20 | 검수 |

검수에서 쌓아야 할 것은 예측값과 정정값의 쌍이다. 정정된 역할만 저장하면
무엇이 왜 틀렸는지 알 수 없으므로, 예측 역할·정정 역할·판정 근거(`scores`)·
판정 방식(`method`)을 함께 남긴다. 이게 나중에 규칙을 고칠 때와
자체 모델을 학습시킬 때 모두 쓰인다.

## 구성

| 모듈 | 역할 |
| --- | --- |
| `src/voice_ai/clova.py` | CLOVA Speech 응답 → `Utterance` 정규화, 화자별 묶기 |
| `src/voice_ai/clovanote.py` | 클로바노트 내보내기 텍스트 파서 (API 붙이기 전 중간 입력) |
| `src/voice_ai/roles.py` | 의사 우선 판정 + 나머지 역할 배정 + 신뢰도 |
| `src/voice_ai/refine.py` | 의사 블록에 흡수된 타 화자 발화 표시 |
| `src/voice_ai/terms.py` | 의료 용어 오인식 교정 (자모 유사도 + 문서 내 근거) |
| `src/voice_ai/qa.py` | 질문-답변 페어링, 사전질문 대조 |
| `src/voice_ai/models.py` | 공유 데이터 모델과 출력 계약 |

## 실제 녹음에서 배운 것

진료 녹음 1건(클로바노트 전사)을 앵커로 돌려보고 세 가지를 고쳤다.
`tests/test_clovanote.py`가 같은 구조를 합성 데이터로 재현해 고정하고 있다.

**환자도 질문한다.** 처음에는 질문 비율이 높으면 매니저로 봤는데, 재진 상담에서
환자가 자기 상태를 직접 물었다("저번이랑 비교해서 많이 나빠진 건가요?").
구조 특징은 어휘 근거를 보강만 하고 역할을 새로 만들지 못하게 했다. 질문한다고
매니저가 아니라 대리 질문 화법이 있어야 매니저다.

**환자는 증상을 호소하지 않는다.** 재진에서는 설명을 듣고 짧게 반응하는 쪽이다.
1인칭 증상 신호만 보던 것을 수용 반응("알겠습니다", "해야겠네요")과
자기 행위 서술("~기는 해요")까지 넓히고, 비의료인 화자의 기본값을 환자로 뒀다.

**판정 불가를 인정해야 한다.** 마지막에 인사말만 남긴 화자는 어휘 신호가 0이었다.
억지로 배정하는 대신 `UNKNOWN`과 경고로 넘긴다. 신뢰도도 전역이 아니라 화자별로
계산한다. 판정 불가 화자 하나가 의사 판정의 확신까지 끌어내리면 안 된다.

## 출력 계약은 `session_reports`에 맞춘다

보들에는 이미 동행 특화 리포트 스키마가 있다(`bodeul.session_reports`,
"동행 종료 시 매니저가 작성하는 진료와 복약 결과의 PostgreSQL 운영 원본").
일반적인 SOAP 노트 대신 이 컬럼들을 그대로 채운다. `ReportDraft`가 1:1 대응이다.

매니저가 손으로 쓰던 리포트를 AI가 초안으로 채우고 매니저가 확정하는 구조다.
제품 흐름에도 맞고, 판단 책임이 사람에게 남는다는 점에서도 맞다.

주의할 것이 둘 있다.

- `companion_session_artifacts.purpose`는 현재 `PAYMENT_EVIDENCE`와
  `PRESCRIPTION_IMAGE`만 허용한다. 진료 음성을 여기 보관하려면 마이그레이션이 필요하다.
- 녹음·분석 동의는 기존 `consent` 도메인(`GuardianSharingConsent`)에 붙이는 것이
  자연스럽다. 건강정보는 민감정보라 별도 동의가 필요하다.

## 아직 확인되지 않은 것

- **용어 사전 확보.** `terms.py`가 오인식을 잡아내려면 약품·질환·검사명 사전이
  있어야 한다. 진료과별로 실제 쓰이는 용어를 모으는 일이 남아 있다.
- **구어체 정리.** 전사 원문은 필러와 중복이 많아 그대로 리포트에 쓸 수 없다.
  정리는 LLM이 맡되 원문을 반드시 함께 보관한다. 의료 기록이라 대조가 가능해야 한다.

## 의료 용어 오인식 교정

앵커에서 "간 보호제"가 같은 대화 안에서 한 번은 맞게, 한 번은 "관보제"로 전사됐다.
사람이 이걸 알아보는 근거는 셋이다. 올바른 형태가 같은 문서에 이미 나왔고,
발음이 비슷하고, 문맥이 간 이야기였다. 앞의 둘은 규칙으로 재현된다.

한글을 자모로 풀고(겹모음까지 분해해야 간/관이 거리 1로 잡힌다) 사전 용어와의
유사도를 잰다. 올바른 형태가 같은 전사문에 이미 있으면 `IN_DOCUMENT`로 표시하는데,
이게 가장 믿을 만한 근거다. 같은 진료에서 같은 약을 두 번 말하는 일은 흔하고
STT가 두 번 다 똑같이 틀리는 일은 드물다.

한쪽이 다른 쪽을 품고 있으면 건너뛴다. "지방간은"은 오인식이 아니라 조사가 붙은
것이고 "복부내장지방"은 더 큰 말의 일부다. 이 규칙 하나로 앵커의 오탐 5건이 사라졌다.

**교정은 제안만 하고 원문을 덮어쓰지 않는다.** 약 이름을 잘못 고치면 리포트가
조용히 틀린 채로 나간다. 확정은 운영자가 한다.

다만 이건 사후 교정이다. **먼저 할 일은 CLOVA Speech 키워드 부스팅에 용어를
등록해서 오인식 자체를 줄이는 것이다.** `terms.py`는 부스팅이 놓친 것을 받는 그물이다.

## 화자분리 오류 대응

앵커에서 두 가지가 실제로 확인됐다.

**흡수.** 긴 의사 설명 안에 환자의 짧은 응답이 통째로 들어가 있었다
("운동 열심히 해야겠네요", "알겠습니다"). CLOVA는 세그먼트마다 화자를 하나만 붙인다.
`refine.flag_foreign_sentences`가 역할 확정 후 역방향으로 훑어 이런 문장을 표시한다.
표시만 하고 재배정하지는 않는다. 한 문장으로 화자를 단정하기에는 근거가 얇고,
잘못 옮기면 의사 발언과 환자 발언이 뒤바뀌어 리포트가 틀어진다.

**과분할.** 한 사람이 여러 화자로 쪼개져 나왔다(앵커의 참석자 2와 3은 같은 사람).
`classify(merge_non_doctor=True)`로 비의사 화자를 한 사람으로 합쳐 판정한다.
의사만 정확히 갈라내면 되므로 이 병합은 목적을 해치지 않는다. 다만 텍스트만으로
동일인 여부를 알 수는 없어 호출자가 판단해 넘겨야 한다. 자동 판단에는 성문이 필요하다.

## 현재 상태와 다음 작업

지금은 **규칙 기반 베이스라인**이다. 남은 작업:

1. **CLOVA 응답 스키마 확정** — `clova.py`는 `speaker.label`과 `diarization.label`을
   모두 받아들이는 방어적 파싱 상태다. 실제 응답을 픽스처로 넣고 좁혀야 한다.
2. **매니저 성문 등록** — ECAPA-TDNN 임베딩 등록·매칭. `classify(manager_speaker_tag=...)`
   자리는 이미 비워뒀다.
3. **온프레미스 LLM 연결** — 규칙 점수를 사전 확률로 넘기고 최종 판정과 요약을 맡긴다.
4. **화자분리 오류 보정** — 역할 확정 후 역방향으로 오배정 발화를 재배정한다.
5. **HTTP 계층** — Core API가 호출할 엔드포인트.

## 주의

실제 진료 음성과 전사 결과는 **민감정보(건강정보)** 다. 저장소에 커밋하지 않는다.
`.gitignore`가 오디오 파일과 `data/real/`, `clova_raw_*.json`을 막아두고 있다.
테스트 픽스처는 합성 데이터만 쓴다.
