# 보들 음성 분석 (온프레미스)

동행 매니저가 녹음한 진료 음성에서 **의사 · 환자 · 매니저**를 구분하고,
매니저가 대신 물어본 질문과 의사의 답변을 짝지어 보들 Core API로 돌려주는 서비스.

```
매니저 앱 (녹음)
   │
   ▼
Core API ── 오디오 ──▶ CLOVA Speech (NCP 국내 리전)
   │                      │ STT + 화자분리
   │                      ▼
   │         speaker_1/2/3 + 타임스탬프 + 텍스트
   │                      │
   │                      ▼
   │              온프레미스 AI  ← 이 저장소
   │              ① 매니저 성문 매칭 → 매니저 확정
   │              ② 나머지 역할 판정 (의사/환자)
   │              ③ Q&A 페어링 + 사전질문 대조
   │                      │
   ◀────── 구조화 JSON ────┘
   ▼
Supabase PostgreSQL → 동행 리포트
```

진료 내용 분석은 온프레미스에서 끝난다. CLOVA Speech는 NCP 국내 리전이라
국외 이전에 해당하지 않는다.

## 설계 핵심

**화자 단위로 판정한다.** 발화 하나하나를 분류하면 "네", "음..." 같은 짧은 응답에서
계속 흔들린다. 화자별로 발화를 전부 모아 한 번에 역할을 배정한다.

**매니저는 성문으로 고정한다.** 매니저는 플랫폼 소속 검증 인력이므로 자격 심사 때
음성 샘플을 받아두면 이후 모든 녹음에서 확정된다. 3명 중 1명이 확정되면 나머지는
"의사 vs 환자" 2택이 되어 난이도가 절반으로 떨어진다.

**사전 질문을 등록받는다.** 동행 요청 시 환자·보호자가 물어볼 질문을 등록하면
Q&A 매칭이 추론이 아니라 대조가 되고, 매니저가 빠뜨린 질문도 잡아낼 수 있다.

## 구성

| 모듈 | 역할 |
| --- | --- |
| `src/voice_ai/clova.py` | CLOVA 응답 → `Utterance` 정규화, 화자별 묶기 |
| `src/voice_ai/roles.py` | 화자 단위 역할 판정 + 신뢰도 |
| `src/voice_ai/qa.py` | 질문-답변 페어링, 사전질문 대조 |
| `src/voice_ai/models.py` | 공유 데이터 모델과 출력 계약 |

## 현재 상태와 다음 작업

지금은 **규칙 기반 베이스라인**이다. 합성 픽스처(`tests/fixtures/sample_clova.json`)에서
역할 판정과 Q&A 페어링이 동작하는 것까지 확인했다.

남은 작업:

1. **CLOVA 응답 스키마 확정** — `clova.py`는 `speaker.label`과 `diarization.label`을
   모두 받아들이는 방어적 파싱 상태다. 실제 응답을 픽스처로 넣고 좁혀야 한다.
2. **매니저 성문 등록** — ECAPA-TDNN 임베딩 등록·매칭. `classify(manager_speaker_tag=...)`
   자리는 이미 비워뒀다.
3. **온프레미스 LLM 연결** — 규칙 점수를 사전 확률로 넘기고 최종 판정과 요약을 맡긴다.
4. **화자분리 오류 보정** — 역할 확정 후 역방향으로 오배정 발화를 재배정한다.
5. **HTTP 계층** — Core API가 호출할 엔드포인트.

## 주의

실제 진료 음성과 전사 결과는 **민감정보(건강정보)** 다. 저장소에 커밋하지 않는다.
`.gitignore`가 오디오 파일과 `data/real/`, `clova_raw_*.json`을 막아두고 있다.
테스트 픽스처는 합성 데이터만 쓴다.
